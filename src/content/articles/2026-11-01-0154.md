## 한눈에 보기
- AWS는 코딩 에이전트가 만든 웹 앱을 배포 없이 즉시 브라우저에서 확인하는 세션 엔드포인트를 공개했습니다.
- 오픈AI는 사이트 운영자가 한 번에 여러 AI에 학습 거부 의사를 밝힐 수 있는 IETF 기반 공통 신호를 도입합니다.
- IBM은 베이스 모델 재학습 없이 어댑터만 교체해 모델을 소프트웨어 패치처럼 업데이트하는 Granite Switch 4.1.1을 발표했습니다.

## AWS: 코딩 에이전트 결과물을 브라우저에서 즉시 검토
**무엇이 발표됐나**
AWS는 아마존 베드록 에이전트코어 런타임(Amazon Bedrock AgentCore runtime)에 '세션 엔드포인트(Session endpoints)' 기능을 추가했다고 밝혔습니다. 에이전트 런타임은 에이전트 작업을 격리된 가상 머신(microVM) 안에서 실행하는데, 세션 엔드포인트를 쓰면 이 세션 내부에서 구동되는 웹 앱에 안전하게 접근할 수 있는 전용 URL이 발급됩니다.

**무엇이 달라지나**
지금까지는 코딩 에이전트가 코드를 짜더라도 별도 호스팅 공간에 배포해야 결과를 볼 수 있어 피드백 주기가 길어졌습니다. 새 방식을 적용하면 가상 머신 안에서 실행 중인 개발 서버의 화면이 브라우저에 실시간으로 연동됩니다. 예를 들어 Claude Haiku 5.5 기반 에이전트에 다크 모드 적용을 요청하면, 파일이 저장되는 즉시 웹소켓 기반 핫 리로드(새로고침 없이 변경 사항을 반영하는 기술)를 통해 브라우저 화면이 바로 바뀝니다. 인증은 AWS의 SigV4 서명이나 JWT 방식을 거치며, 개발자가 지정한 포트(8000~12000 범위 내 1~5개)만 접근할 수 있어 보안을 유지한 채 개발 루프를 수 초 단위로 단축합니다.

## 오픈AI: 웹사이트 학습 거부 설정을 하나의 공통 규격으로 통일
**무엇이 발표됐나**
오픈AI는 웹사이트 운영자가 AI 모델 학습용 데이터 수집에 대한 선호도를 표기할 수 있는 공통 신호를 robots.txt에 지원하겠다고 발표했습니다. 이는 국제인터넷표준화기구(IETF) 산하 AI 환경설정 작업반(AI Preferences working group)의 표준화 작업에 기반을 둡니다.

**무엇이 달라지나**
웹사이트 운영자들은 그동안 각 AI 기업의 크롤러(웹 데이터를 자동 수집하는 소프트웨어) 이름을 일일이 찾아 개별 차단 규칙을 robots.txt에 작성해야 했습니다. 새 신호 규격이 정착되면 단 하나의 규칙으로 협력에 참여하는 복수의 AI 제공업체에 동일한 학습 수집 거부 의사를 전달할 수 있습니다. 기존 오픈AI 크롤러 제어 방식도 계속 유지되며, 오픈AI는 수개월 내 실제 구현을 마치고 세부 사항을 공유할 예정입니다.

## IBM·허깅페이스: 거대 모델도 일반 소프트웨어처럼 패치 업데이트
**무엇이 발표됐나**
IBM은 허깅페이스 블로그를 통해 모듈형 아키텍처 모델인 'Granite Switch 4.1.1'을 공개했습니다. 이 릴리스는 이전 버전(4.1)과 완벽히 호환되는 패치 형태의 마이너 업데이트입니다.

**무엇이 달라지나**
방대한 파라미터를 가진 기초 모델(Base model) 전체를 다시 학습시키는 대신, 특정 작업에 특화된 어댑터만 교체했습니다. 기본 모델은 그대로 둔 채 10개 언어를 지원하는 음성 인식(ASR) 모델과 의사결정 인덱스 성능이 개선된 Decision 어댑터만 새로 갈아 끼운 것입니다. IBM은 타사 및 개발자가 자체 어댑터를 만들어 일반 소프트웨어를 배포하듯 모델을 고도화할 수 있도록 어댑터 SDK와 튜토리얼을 향후 제공할 계획입니다.

## 왜 중요한가
이번 발표들은 AI 기술이 초기 연구 단계를 지나 '기존 소프트웨어 공학의 표준' 안으로 편입되고 있음을 명확히 보여줍니다.

첫째, 개발 속도 향상입니다. AWS는 에이전트 생성물을 배포 단계 없이 실시간 렌더링하도록 묶어 일반 웹 개발 환경과 동등한 생산성을 구현했습니다. 둘째, 데이터 거버넌스의 표준화입니다. 오픈AI가 IETF 논의에 맞춰 단일 신호를 채택하기로 한 것은 무분별한 웹 크롤링 논란을 줄이고 인터넷 규약을 따르는 정규 인프라로 자리 잡으려는 시도입니다. 셋째, 유지보수 비용 절감입니다. IBM의 사례처럼 거대 모델을 통째로 재학습하지 않고 모듈형 어댑터만 패치하는 방식은 AI 서비스의 운영 지속 가능성을 크게 높입니다. AI의 개발, 데이터 수집, 유지보수 전 영역이 전통적인 IT 체계처럼 안정화되고 있습니다.

## 앞으로 지켜볼 점
- 오픈AI 외 다른 주요 AI 개발사들이 IETF의 공통 robots.txt 표준에 얼마나 참여할지 여부
- 코딩 에이전트의 실시간 실행 환경이 AWS 외 다른 클라우드 및 로컬 IDE 생태계로 얼마나 확장될지
- 모델 모듈화(어댑터 방식)가 거대 언어 모델의 주기적 버전 업데이트 표준으로 안착할 수 있을지
