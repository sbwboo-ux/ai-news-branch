## 한눈에 보기
- AWS는 단일 입력 응답을 넘어 여러 단계 행동의 최종 결과만으로 모델을 학습시키는 멀티턴 강화학습(MTRL) 환경을 Amazon SageMaker AI에 공개했습니다.
- OpenAI는 10억 명이 넘는 ChatGPT 사용자를 안정적으로 지원하기 위해 자체 스토리지 플랫폼 'Habitat'과 Azure Cosmos DB의 멀티테넌시 구조를 최적화한 경험을 공유했습니다.
- 앨런 인공지능 연구소(Ai2)와 유펜 연구진은 기존 문헌을 실시간으로 분석해 연구 초안의 문제점과 수정안을 역동적으로 제안하는 도구 'LitPivot'을 발표했습니다.

## AWS: 여러 단계의 행동을 평가하는 '멀티턴 강화학습' 파이프라인

### 무엇이 발표됐나
AWS가 Amazon SageMaker AI 상에서 에이전트의 다단계 행동 과정을 훈련할 수 있는 멀티턴 강화학습(Multi-Turn Reinforcement Learning, MTRL) 파이프라인 가이드를 공개했습니다. 기존 지도학습 미세조정(Supervised Fine-Tuning)이나 단발성 강화학습은 한 번의 질문에 좋은 답변을 내는 데 맞춰져 있어, 여러 단계에 걸쳐 외부 도구를 사용하고 환경과 상호작용하는 에이전트 작업에는 한계가 있었습니다.

이번에 소개된 방식은 Amazon Bedrock AgentCore 런타임에 호스팅된 에이전트 환경과 SageMaker AI의 훈련 작업을 연동합니다. 훈련 작업은 에이전트를 호출해 작업을 끝까지 수행하게 한 뒤, 에피소드가 끝났을 때 주어지는 최종 보상(Reward) 신호 하나만을 수집합니다. 이를 기반으로 그룹 상대 정책 최적화(GRPO, 여러 시도의 상대적 점수 차이를 이용해 모델을 업데이트하는 강화학습 알고리즘)와 LoRA(Low-Rank Adaptation, 원본 모델 가중치를 고정한 채 적은 양의 추가 파라미터만 학습하는 효율적 미세조정 기법)를 활용해 정책 모델을 점진적으로 개선합니다.

### 무엇이 달라지나
정답 경로가 정해져 있지 않은 복잡한 업무를 기업 맞춤형 소형 모델로 해결하기 쉬워집니다. 워들(Wordle) 게임을 예시로 진행한 실험에서, 오픈 모델인 GPT-OSS-20B는 기본 추론 강도 기준으로 미훈련 단어 해결률이 61%에서 84%로 향상되었습니다. 인프라 인스턴스를 직접 구성할 필요 없이 서버리스 형태로 토큰 단위(입력·샘플링·역전파 훈련 토큰) 비용만 청구되며, 해당 실험의 훈련 토큰 비용은 약 339달러 수준에 불과했습니다. 기업 내부 고유 업무 흐름을 다루는 저비용 고성능 전문 에이전트를 구축할 수 있는 진입 장벽이 낮아졌습니다.

## OpenAI: 10억 사용자를 지탱하는 스토리지 플랫폼 'Habitat'의 확장기

### 무엇이 발표됐나
OpenAI는 40개 지리적 리전에서 10억 명 이상의 사용자 트래픽을 밀리초 단위 응답 속도로 처리하는 자체 애플리케이션 스토리지 플랫폼 'Habitat'의 두 번째 아키텍처 포스트를 공개했습니다. 이번 발표는 기저 저장소인 Azure Cosmos DB를 대규모 글로벌 환경에서 어떻게 확장하고 운영했는지에 초점을 맞췄습니다.

초기에는 단일 컨테이너 기반으로 시작했으나, 사용자 ID나 워크스페이스 ID 같은 논리적 파티션 키가 여러 제품 기능 간에 충돌하며 처리량 한계(기본 10,000 RU/s)에 도달했습니다. 또한 하나의 물리적 파티션을 공유하는 다른 논리 파티션들이 과도한 부하를 유발하는 '노이즈 이웃(Noisy Neighbor, 특정 사용자의 높은 부하가 인접 시스템에 영향을 주는 현상)' 문제와 데이터 증가로 인한 물리 파티션 분할 시 개별 파티션의 실효 처리량이 줄어드는 '약한 파티션(Weak Partitions)' 문제를 겪었습니다. OpenAI는 Azure 팀과의 협업을 통해 공동 관리 컨테이너 기반의 멀티테넌시(Multi-tenancy, 하나의 시스템 자원을 여러 제품 및 조직이 나누어 쓰는 구조) 방식을 채택하며 이를 해결해 나가고 있습니다.

### 무엇이 달라지나
초거대 AI 서비스를 운영할 때 모델 서빙뿐 아니라 그 아래를 받치는 온라인 데이터베이스 설계가 얼마나 치명적인지 보여줍니다. 각 제품 팀이 독자적으로 인프라를 프로비저닝하는 싱글테넌시 구조는 비용과 자원 낭비가 큽니다. 반면 중앙화된 멀티테넌시로 전환하면 효율은 높아지지만 격리 문제가 발생합니다. OpenAI는 Cosmos DB의 기본 원시 기능을 최대한 활용하면서도 핫키(Hot key) 부하를 방어하고, 캐싱 및 리스(lease) 설계를 통해 500페타바이트(PB) 이상의 데이터를 글로벌 규모로 안정화하는 운영 노하우를 정립했습니다.

## 앨런 AI 연구소: 논문 지형을 보며 연구 방향을 바꾸는 'LitPivot'

### 무엇이 발표됐나
앨런 인공지능 연구소(Ai2)와 펜실베이니아 대학교 연구진은 연구자가 선행 연구를 검토하면서 연구 계획을 역동적으로 수정하도록 돕는 시스템 'LitPivot'을 발표했습니다. 연구 도중 기존 논문을 확인하고 연구의 방향을 틀거나 차별점을 다시 세우는 과정을 '문헌 유발 피봇(Literature-initiated pivot)'이라고 부릅니다.

LitPivot은 연구 제안서를 '문제(Problem)', '제안 기여점(Proposed Contribution)', '평가 계획(Evaluation Plan)'이라는 세 가지 측면(Facet)으로 자동 분할합니다. 연구자가 특정 영역을 선택하면 학술 검색 엔진(Asta Paper Finder)으로 찾은 관련 논문들이 해당 영역에 맞춰 그룹화되고 순위가 매겨집니다. 시스템은 단순히 문헌을 요약하는 데 그치지 않고, 선택한 논문들의 한계점과 근거 문장을 직접 인용하며 연구 제안에 대한 비판적 평가와 구체적인 수정 문안을 제안합니다.

### 무엇이 달라지나
17명의 연구자를 대상으로 진행한 실험 평가에서 전문가들은 LitPivot으로 다듬은 제안서가 단순 텍스트 편집기와 AI 챗봇을 병용한 통제군보다 문헌적 근거가 유의미하게 탄탄하다고 평가했습니다. 한 참가자는 '합성 의료 기록 생성' 아이디어로 시작했으나, LitPivot의 문헌 분석을 거치며 '다회 방문 간 모순 감지'로 연구 범위를 좁혀 독창성을 확보했습니다. AI가 연구자를 대신해 글을 써주는 것이 아니라, 선행 연구와의 비교를 통해 아이디어의 빈틈을 메워주는 전문 협업 도구의 실질적 가능성을 입증했습니다.

## 왜 중요한가
이번 세 발표는 AI 생태계가 '단발성 텍스트 질의응답'이라는 1차원적 활용 단계를 벗어나 시스템적 성숙기에 들어섰음을 보여줍니다.

첫째, **모델 훈련의 패러다임 전환**입니다. AWS가 보여준 MTRL 파이프라인처럼, 이제 모델은 한 문장의 정답을 맞히는 학습이 아니라 여러 번의 상호작용 끝에 비즈니스 목표를 완수하는 '에이전트적 행동'을 직접 보상받아 학습합니다.

둘째, **실서비스 인프라의 현실적 한계 극복**입니다. 10억 명의 대화 세션과 데이터를 영속화하려면 기존 분산 데이터베이스의 파티셔닝 구조를 극한으로 쥐어짜야 합니다. OpenAI의 Habitat 사례는 AI 애플리케이션의 성공이 모델 파라미터 수뿐 아니라 데이터베이스 레이어의 정교한 아키텍처에 달려 있음을 방증합니다.

셋째, **전문가 인지 워크플로우 지원**입니다. LitPivot은 AI를 단순한 챗봇이 아닌 '구조화된 비평 파트너'로 배치했습니다. 모델은 이제 사용자의 단편적 질문을 기다리는 수동적 도구가 아니라, 거대한 외부 지식베이스(문헌)와 상호작용하며 인간의 복잡한 의사결정을 실시간으로 보조하는 역할을 맡고 있습니다.

## 앞으로 지켜볼 점
- **소형 특화 모델의 부상**: AWS MTRL과 같은 강화학습 파이프라인을 통해 기업 내부 워크플로우에 특화된 20B~30B급 저비용 오픈소스 모델의 성능이 대형 프론티어 모델을 얼마나 빠르게 대체할지 주목됩니다.
- **AI 네이티브 스토리지 표준화**: OpenAI가 겪은 Cosmos DB의 물리 파티션 제약과 핫키 문제는 다른 AI 기업들도 직면할 과제입니다. 멀티테넌트 환경에서 에이전트 메모리와 대화 로그를 다루는 스토리지 아키텍처 표준이 어떻게 정립될지 지켜볼 필요가 있습니다.
- **연구·전문 작업용 상호작용 인터페이스의 진화**: LitPivot처럼 입력 텍스트를 구조적으로 쪼개고 외부 데이터 소스와 동적으로 엮어내는 UI/UX가 법률, 금융, 엔지니어링 등 다른 지식 집약 분야로 어떻게 확장될지 기대됩니다.
